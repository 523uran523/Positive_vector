# HANDOFF_TO_CODEX — Передача проекта «Позитив Вектор»

Этот документ содержит технические заметки для проверки, сборки и развёртывания проекта на Linux-сервере или Android + Termux.

## 1. Ключевые архитектурные решения
1. **Нулевая нативная компиляция SQLite (`node:sqlite`)**:
   - Вместо `better-sqlite3` (который часто падает при компиляции `node-gyp` / NDK в Termux на Android) использован встроенный модуль Node.js `node:sqlite` (`DatabaseSync`, проверено на Node `v22.23.2`).
   - Включены `PRAGMA foreign_keys = ON`, `PRAGMA journal_mode = WAL` (для файловой БД) и `PRAGMA busy_timeout = 5000`.
2. **Точность расчётов**:
   - Денежные суммы хранятся в целых копейках (`*_kopecks`).
   - Количества на складе хранятся в тысячных долях (`*_milli`, 1 единица = `1000`).
3. **Защита и отсутствие захардкоженных паролей**:
   - В исходном коде нет жёстко заданных паролей.
   - При пустой базе доступен одноразовый веб-мастер настройки (`POST /api/auth/setup`), который блокируется после создания первого пользователя (`409 Conflict`).
   - Скрипты `npm run create-admin` и `npm run seed:demo` генерируют криптостойкие случайные пароли через `crypto.randomBytes` и выводят их однократно в stdout.
4. **Анти-двойное списание на складе (`server/services/warehouseService.ts`)**:
   - При выдаче материала (`issue`) остаток на складе уменьшается сразу.
   - При последующем списании в расход (`consume`) по этому же заказу вычитается только перерасход сверх ранее выданного (`Math.max(0, qty - unconsumedIssuedMilli)`).
   - Возврат (`return`) ограничен неиспользованным остатком на заказе.
5. **Многодневные заказы**:
   - Заказ завершается автоматически только тогда, когда у него есть хотя бы один не отменённый выезд и все такие выезды получили отчёт о завершении. Заказ без выездов не завершается самопроизвольно.

## 2. Адаптация для Android + Termux
- **Версия Node.js**: требуется Node.js `>= 22.13` (в Termux: `pkg install nodejs` обычно ставит актуальную LTS 22+/24+ с поддержкой `node:sqlite`).
- **Запуск в production на Termux**:
  - В `package.json` скрипт `"start"` сейчас равен `"node server.ts"` (в Node 22.18+ / 23.6+ TypeScript strip-types поддерживается нативно; если на целевом Node.js потребуется явный loader или `tsx`, используйте `npx tsx server.ts` или скомпилируйте `server/` в JS).
  - Также при запуске внутри локальной сети без HTTPS оставляйте `COOKIE_SECURE=false` в `.env`, иначе браузер не сохранит `HttpOnly` cookie по HTTP.
  - Если используется обратный прокси (Nginx/Caddy/Cloudflare Tunnel с HTTPS), установите `COOKIE_SECURE=true` (`app.set('trust proxy', 1)` уже включён).
- **Уведомления на email**:
  - В таблице `settings` заложено поле `email_notifications`, однако реальная отправка SMTP не подключалась во избежание жёсткой привязки к внешним сервисам; при необходимости можно подключить `nodemailer` в `server/security.ts`.

## 3. Проверка и статус инструментов
- **Автотесты (`npm test`)**: пройдены (`tests/businessRules.test.ts`, 5 сценариев на реальном Express + `:memory:` SQLite: первичная настройка, CSRF, блокировка подбора паролей, скрытие цен от сотрудника, многодневное автозавершение заказа, смены в цеху со снимком ставки, склад без двойного списания + отрицательный остаток, финансы без задвоения и XLSX без секретов).
- **Сборка и типы (`npm run build`, `npm run lint`)**: смотрите результат финальной проверки перед передачей.
- **Фактическое поведение PWA на реальном Android-устройстве и живой запуск на Termux**: требуют ручной проверки после развёртывания (в контейнере сборки нет реального Android/Termux окружения).
