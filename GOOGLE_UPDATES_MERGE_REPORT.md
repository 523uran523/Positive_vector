## 6. Решения и целостность
Заказ с платежами, расходами, складскими операциями, отчётами или начислениями не удаляется: API возвращает 409 и предлагает отмену. Материалы/инструменты с историей либо плановыми назначениями защищены от каскадного удаления. Выданные инструменты защищены отдельно. Компании/контакты с заказами или платежами не удаляются. Аудит удаления клиентов атомарен.
При удалении последнего отчёта завершённый выезд и заказ переоткрываются. При удалении основного отчёта с оставшимися отчётами выбирается замена. Файлы удаляются через долговечную очередь; ошибки удаления сохраняются для повторной очистки. Непривязанные файлы старше суток после сбоя загрузки также подлежат очистке.

## 7. Схема и офлайн-синхронизация
Добавлена миграция `002_sync.sql`: `mutation_receipts` и `file_deletions`. В рабочую БД миграция этой сессией не применялась; миграции проверены на тестовых БД.
Для операции сохраняется уникальный ID до отправки. Изменения БД и квитанция результата фиксируются одной транзакцией; вложенные бизнес-транзакции используют savepoint. Повтор возвращает сохранённый результат. Изменённый payload под тем же ID отклоняется. Квитанции разделены по пользователям и области прав.
Версии записей вычисляются через HMAC. Устаревшие PATCH/PUT/DELETE получают 409; удалённые записи — 404. Версия проверяется внутри транзакции. Service Worker обрабатывает API только через сеть и не хранит личные API-ответы.
IndexedDB-кэш/очередь привязаны к аккаунту; смена аккаунта очищает их. Выход очищает локальные данные и блокирует автоматическое восстановление прежней cookie-сессии в интерфейсе. 401 останавливает отправку; очередь сохраняется для повторного входа того же пользователя. Смена пользователя в другой вкладке контролируется событиями storage и идентификатором пользователя в ответе API. Очередь сохраняет порядок и использует блокировку между вкладками там, где доступен Web Locks API; серверная идемпотентность действует независимо.
Лимиты: 100 операций, 40 МБ очереди, 13 МБ одной операции, 12 МБ серверной загрузки файла. Ошибки сохранения не выдаются за успех. Операции старше 30 дней отклоняются; квитанции очищаются через 45 дней. Конфликт сохраняется с сообщением и блокирует последующие операции до решения пользователем.
