# Позитив Вектор — CRM/ERP-система

Адаптивная CRM/ERP-система в формате PWA для компании по изготовлению и монтажу рекламных баннеров, декораций, вывесок и металлоконструкций.

Подробный [путеводитель пользователя](docs/USER_GUIDE.md). Инфраструктура телефона и её ограничения описаны в [TecnoServer](https://github.com/523uran523/TecnoServer).

Порядок обновления версии на телефоне, проверок и откат — в [deployment/termux/UPDATE.md](deployment/termux/UPDATE.md).

## Общий чат и уведомления

В общем чате и до пяти дополнительных чатах доступны текст, файлы и голосовые сообщения. Дополнительные чаты создаёт администратор и добавляет в них участников; участники видят всю историю своего дополнительного чата. Доступ к прошлой истории общего чата для нового сотрудника выбирается администратором при создании учётной записи и затем не меняется. Сообщение можно удалить автору или администратору, имеющему доступ к чату; автор может редактировать его в течение 5 минут, а администратор свои — в течение 24 часов.

Администратор может исключать участников из дополнительных чатов и удалять такие чаты; удалённый чат скрывается, а его история сохраняется в базе. Общий чат удалить или исключить из него сотрудника нельзя. В настройках администратора доступен переход к управлению сотрудниками: увольнение закрывает действующие сеансы и переносит учётную запись в отдельный список, сохраняя историю и расчёты. После повторного входа уволенный видит только статус увольнения и актуальный остаток к выплате; остальные маршруты API недоступны. При восстановлении прежний пароль снова действует; приложение напоминает его сменить. Если при увольнении осталась открытая смена, она не закрывается автоматически и требует сверки.

Для Web Push необходимо самостоятельно создать пару ключей командой `npx web-push generate-vapid-keys` и задать `WEB_PUSH_PUBLIC_KEY`, `WEB_PUSH_PRIVATE_KEY` и `WEB_PUSH_SUBJECT` в окружении сервера. Приватный ключ хранится только на сервере. Каждый сотрудник включает уведомления на каждом устройстве отдельно. На iPhone приложение нужно добавить на экран «Домой». При выходе из учётной записи подписка текущей сессии удаляется. Для работы микрофона необходим HTTPS и разрешение пользователя. Файлы чата и аватары включаются в резервную копию.

Без настройки ключей чат и счётчик непрочитанных работают, а кнопка уведомлений сообщает, что push ещё не настроен. Чат требует сети: сообщения не ставятся в офлайн-очередь.

## Стек технологий

- **Frontend**: React 19, TypeScript, Vite, Tailwind CSS v4, `vite-plugin-pwa`, `lucide-react`
- **Backend**: Node.js (`>= 22.13` со встроенным `node:sqlite`), Express, TypeScript (`tsx`)
- **База данных**: SQLite (`node:sqlite`, режим `WAL`, внешние ключи `PRAGMA foreign_keys = ON`, миграции, `BEGIN IMMEDIATE` транзакции)
- **Авторизация и безопасность**: `crypto.scryptSync`, HTTP-only cookie (`pv_session`), CSRF-токены (`X-CSRF-Token`), ограничение попыток входа (`login_attempts`), строгий серверный RBAC
- **Файлы и экспорт**: `multer` (дисковое хранилище в `UPLOAD_DIR` с проверкой прав доступа при скачивании), экспорт в `.xlsx` через `xlsx`

## Быстрый запуск

### 1. Установка зависимостей
```bash
npm install
```

### 2. Переменные окружения
Скопируйте `.env.example` в `.env` и при необходимости задайте параметры:
- `PORT=3000`
- `DB_PATH=./data/pozitiv_vektor.sqlite`
- `UPLOAD_DIR=./data/uploads`
- `SESSION_SECRET=<случайная-длинная-строка>`
- `COOKIE_SECURE=false` (`true` только при работе за HTTPS)
- `SESSION_TTL_HOURS=168`

### 3. Миграция базы данных
```bash
npm run migrate
```

### 4. Первый запуск и учётные записи
Вариант А (веб-интерфейс): откройте приложение в браузере — при пустой таблице `users` появится экран первоначальной настройки первого администратора (можно сгенерировать случайный одноразовый пароль или задать свой).

Вариант Б (CLI — создание/сброс администратора со случайным паролем):
```bash
npm run create-admin
```

Вариант В (демо-данные с 1 администратором, 1 монтажником, заказами, складом и финансами; пароли генерируются случайно и выводятся 1 раз в консоль):
```bash
npm run seed:demo
```

### 5. Режим разработки и сборка
```bash
# Разработка (Express + Vite HMR middleware на одном порту)
npm run dev

# Сборка фронтенда и проверка типов
npm run build
npm run lint

# Запуск production-сервера
NODE_ENV=production npm start

# Автотесты бизнес-логики
npm test
```

## Работа с файлами и загрузками
Фотографии и документы заказов/выездов загружаются на сервер через `POST /api/orders/:orderId/attachments` (`multipart/form-data`, лимит 12 МБ, допустимые форматы: JPG, PNG, WebP, GIF, PDF, DOCX, XLSX, TXT), сохраняются в `UPLOAD_DIR`, а скачиваются только авторизованным пользователям с доступом к заказу через `GET /api/orders/attachments/:attachmentId`.
